### Проект вебинара 5 октября

Какие проблемы решаем:
1. Понять какая версия кода самая свежая?
2. Как можно понять кто внес конкретное изменение и для какой задачи?
3. Когда вы меняете код, то в репозиторий отправляются только ИЗМЕНЕНИЯ(!!!)

Запишем команды для отправки кода:
- git status - статус репозитория
- git add - какие файлы будет отправлять в репозиторий
- git commit - обязательное описание сделанных изменений
- git push

Совместная работа:
1. Я клонирую себе репозиторий, чтобы сделать отчет по рекламе. Делаю его 2 дня. Исправляем поле в источнике.
2. Что за это время произойдет с репозиторием в гитхабе?

Зачем нам ветки:
1. В названии пишем идентификатор задачи из трекере задач. JIRA, Трекеры, Кайтен, ... Например, ARES-34.
2. Пишем код/делаем изменения для своей задачи.
3. Как проверить, что я ничего не сломал???

В пулреквесте (рекомендации):
1. Призывается ваш коллега, который смотрит бизнес-логику - верно ли посчитали метрики, правильно ли выбран источник ...
2. Вы получаете ревью любой строчки с комментариями вашего коллеги.
3. После того как все поправлено - первый коллега ставит Looks good to me (LGTM) - у первого коллеги пройдено ревью.
4. Призываем второго коллегу на техническое ревью - смотрится про ошибки в коде / кривое форматирование / правильные ли доступы к базе данных / не ли 8-этажных циклов - будет ли вам код вообще работать.
5. Очень здорово настроить нейро-ревью - проверка кода агентами.
6. После того как получили 2 подтверждения можем завершить пулревест.
